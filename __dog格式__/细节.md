# dog 格式

## 0. 最简单的例子

> 用缩进表示父子, 同缩进并列是兄弟, 纯文本的脑图文件格式.

比如文件: 样例.dog, 他的内容如下

```dog
节点a                    
  a的儿子
  a的2儿子
节点b, 他是a的弟弟
  b的大儿子
  b的2儿子
  	b的2儿子的儿子(b是这个节点的爷爷)
```

他的实际脑图树展示: 

* 样例
  * 节点a                    
    * a的儿子
    * a的2儿子
  * 节点b, 他是a的弟弟
    * b的大儿子
    * b的2儿子
      * b的 2儿子的儿子(b是这个节点的爷爷)

其中, 根文本就是文件名, 文件保存时root作为文件名保存, 同样打开文件时, 文件名作为root文本展示, 因此, 有符号转换

| 根文本             | 文件名                   |
| ------------------ | ------------------------ |
| 26-09-12 日记      | 26-09-12_日记.dog        |
| 26-09-12 日记 done | `26-09-12_日记_done.dog` |

* root 文本不占文件内的任何一行.
* 因为是文件名, 所以要考虑平台兼容性, 不要大于120个字符.

## 2. 缩进兼容性

读文件要兼容各种不规范缩进: 层级只按"相对量"推 (比上一行深 = 下一级; 同宽 = 同级; 比上一行浅 = 往上退), 不看绝对宽度; 写回一律规范成"顶层顶格, 每级 2 空格"。

```dog
		一级甲                # 第一行: 不管前面多少空白, 都算顶层 (基准)
 一级乙                       # 宽(0)比上一行小 → 回到顶层
			二级甲            # 比上一行深 → 下一级
			二级乙            # 与上一行同宽 → 同级
		二级丙                # 比二级浅, 但没浅到一级 → 还是二级
一级丙          # 比上级浅, 要降级, 并且比一级浅, 那么他就是一级
            二级丁, 不论多深, 他比上级深, 就只能是2级.
        二级戊, 虽然浅, 但是还是2级.
         三级甲, 比2级深, 那么他就是3级.
     二级己, 比上一个浅, 并且比之前的2级浅, 比之前的1级深, 那么他就是2级.
```

保存为:

```dog
一级甲
一级乙
  二级甲
  二级乙
  二级丙
一级丙
  二级丁, 不论多深, 他比上级深, 就只能是2级.
  二级戊, 虽然浅, 但是还是2级.
    三级甲, 比2级深, 那么他就是3级.
  二级己, 比上一个浅, 并且比之前的2级浅, 比之前的1级深, 那么他就是2级.
```

* 关于首行缩进, 不论是整个文件的第一行, 还是包装块内的第一行, 他们前面的空白字符(回车/空格/tab)都会被忽略, 会被自动剪裁.

## 3. [[[包装块]]] 样例/T2.dog

> 一般而言每行是一个节点, 那么如果节点的文本内容包含回车, 分隔符, 就要用[[[保住本来不支持的符号]]]

### 3.1 例子

* 下面是一个节点, 含回车和各种分隔符

```dog
    ●[[[                     # 独占一行, 缩进和折叠符都生效
  第一行                   # 
  第二行                   # ...
  ----- 父 -----           # ... 
  ●折叠也不生效了           # ...
]]]                     # 闭括号独占一行, 必须无缩进
```

* 一个包含中括号的节点

```dog
[[[[                    # 内容里有 3 连跑闭括号就用 4 个括 (同理 5 括 4, 3 括 2)
    文本第一行
    ]]]                     # 
    第三行
]]]]
```

* 一个节点, 中括号懒惰匹配

```dog

[[[                     # 开括号
      [[[               # 文本
]]]                    # 闭括号匹配
# 这里如果没有这个闭括号, 那么上面的中括号都是普通文本了, 上面就是2个节点(父子关系), 每个节点内容都是`[[[`
```

* 空内容的块等于空行: `[[[`/`]]]` 里面不含内容或者只含空白符号(空格/tab/回车)

### 3.2 文本中如果有这些内容, 那么需要包装

| 文本内容         | 前提                                        |
| ---------------- | ------------------------------------------- |
| 换行 `\n`/`\r`   |                                             |
| `●`              | 行首                                        |
| [[[              | 几乎独占一行(可以有空白和缩进类字符/折叠符) |
| ]]]              | 独占一行                                    |
| -----分隔符----- | 无(这个是串匹配, 因此任何时候都要包装)      |

## 3.3 语法

```dog
      缩进 + ●? + [[[        # 开括号独占一行
内容 (逐行原样, 含空行)
]]]                          # 闭括号独占一行
```

1. 括号独占一行: 跟内容粘一起就数不清了 —— 内容以 `[` 开头时, 开括号连跑会跟它连成一段, 切不开 (实证: 试过 inline 写法, `[[[abc]]]` 往返成 `abc`)
2. 括号数 = `max(3, 内容里最长 `]` 连跑 + 1)`: 定长 3 时, 内容里恰好有一行 `]]]` 会被当闭括号, 块提前结束

## 6. 实际的实现逻辑参考

* 解析逻辑:
  1. 拆尾部两区 (父/形), 兼容两区任意先后
  2. 剩余正文按 `----- 昭 -----` 拆左右子树
  3. 各自用缩进栈推断父子关系; 行首 `●` 剥离后识别为折叠节点
  4. root 文本 = 文件名还原 , 不存在于文件内容中

* 第三步缩进解析逻辑:
  * 缩进容错: 兼容 tab 和不规则空格, 统一转为空格后按相对缩进量推断层级.
  * **缩进栈**: 哨兵打底, 每行弹栈找到缩进比自己小的作为父节点, 再入栈. 标准的缩进解析模式.
* 节点id逻辑:
  * 为了能够正常合并/变基文档, 因此节点id按照父子顺序组织.
* 磁盘-内存转义逻辑:
  * 磁盘上用-和_代替了内存中的冒号中括号空格. 
  * 内存中的空格有分隔符的含义, 因此为了保持链接dog的完整要用中括号把链接dog括起来.
* 包装块
  * 文本与行结构撞车时 (文本含换行 / 区标记 / 行首 `●` / 整行只有 `[` …), 盘上包成 `[[[...]]]` 块, 载入时摘掉.
  * 落盘顺带把文本首空白剪掉 (`lstrip()`, 原样落盘会被当缩进), 空文本节点不写这一行 (写出去就是空行); 尾空白原样.
* 参考文档: f2_dog_io.md, f2_dog_io_block.md, 这两份文档的描述都比本文档更为简洁.

## 7. 实际对于规则的放宽

1. 缩进: 
   * 不要求初始一级节点缩进为0, 不要求全文档基础缩进为0
   * tab和空格兼容, 每个tab=2空格.
   * 不要求缩进对齐, 也不要求父子缩进固定为2空格.
2. 顺序:
   * 不要求-----父-----和-----形-----之间的顺序关系.
   * 不要求前缀之间的顺序关系(框词, 时间戳)
   * 不要求尾缀之间的顺序关系(符号, 链接)
3. 省略:
   * 没有右子树时, 省略 -----昭------
   * 没有外链对本文的引用时, 省略 -----父-----
   * 默认脑图形式是, 省略 -----形-----
   * 前缀后缀均可以省略
   * 链接可以省略形式名, 只有`xxx.dog`是允许的.
