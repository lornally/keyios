### 处理范式
1. 在自己的项目里面建文件.
2. 自动处理, 导入本项目内容.
3. 因为各个语言方式不同, 所以此种处理方式比引入外部资源的方式更为稳妥.



### 设计

```yaml
# keywords.yaml —— 关键词 → 图标名, 一行一条, key 天然唯一
脑图: 脑图
mindmap: 脑图
mm: 脑图
```

```yaml
# macos.yaml —— 图标名 → SVG, 一个块一个图标
脑图: |
  <svg ...>...</svg>
方格旗右杆: |
  <svg ...>...</svg>
```

### 设计理由

1. icon关键词处理标准的项目目录, 为了兼容python的nuitka编译, 所以文件名和目录名都要纯拉丁字母

1. svg放一个文件, 是因为未来各个平台的svg可能不同, 甚至于不同的theme, svg都可能不同, 如果是散落的文件, 整体的维护就会非常痛苦, 所以我宁肯冗余他, 比如咱们的svg就是macos.yaml
   1. 由此, 关键字yaml和svgyaml要分开的.
2. 你现在的格式有严重的问题, 你不能保证keywords的唯一性, 你懂吗, 你这个映射会出问题. 
   1. 所以原本的py的写法是对的: 
```sh
脑图:脑图
mindmap:脑图
mm:脑图
```
​	这个能保证key的唯一性. 




### 文件

- `keywords.yaml` —— 关键词 → 图标名. key 唯一, 重复即报错.
- `macos.yaml` —— 图标名 → SVG. 平台/theme 一个文件; 以后加 `ios.yaml` / `macos-dark.yaml`, `keywords.yaml` 不动.

### 匹配规则 (消费方实现)

- 分隔符 = 空白 / `_` / 行首尾; 关键词必须是独立 token (`牛奶done` 不匹配, `牛奶 done` 匹配).
- 以"框"结尾且在 `keywords.yaml` 中 = 框词 (可交互状态框); 其余 = 图标.
- 整段文本只有一个词时, 这个词不认作图标/框词 (当正文); 时间戳/链接不受此限.
- `1.1`-`9.9` 是普通图标条目 (小数编号徽标).

### 各语言包

- `python/` —— `pip install <本目录>/python`; `from cat import 关键词, 图标` (关键词 → 图标名, 图标名 → SVG).
- `swift/` —— SPM 包 (`.package(path: ".../cat/swift")`); `import Cat`, 用 `keywords` / `icons` / `icon(for:)`.
- 其它语言按同一范式加目录.

### 生成

改了 YAML 后跑 `python3 tools/build.py` (需 pyyaml), 重新生成 `python/cat/_data.py` 和 `swift/Sources/Cat/Data.swift`. 两个数据文件入库, 消费方运行时不依赖 YAML 库.
