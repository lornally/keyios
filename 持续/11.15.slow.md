顺手用真实文件跑了下解析耗时（`swiftc -O`，1000 次取平均）：

| 文件 | 大小 | 每次解析 |
|---|---|---|
| 26-08-15_重要不急.dog | 5.1 KB | ~38 ms |
| 26-11-15_日记.dog | 1.5 KB | ~24 ms |

比预想慢，原因是 [f3解析dog.swift:215](Keyios/f3解析dog.swift#L215) 这类地方在每行/每个 token 上现编译 `NSRegularExpression`。但这是点开详情时的一次性 30ms 后台开销，导航动画里看不出来；真要优化就是把那些正则提成 `private static let`，一次编译反复用——现在没必要。

唯一和详情页有关的小风险：点开时会再查一次目录、再读一次同名 `.dog`（[p2脑图.swift:399](Keyios/p2脑图.swift#L399)）。首页启动时通常已把文件拉到本地，所以基本是毫秒级；如果那篇还没下载，详情页会转圈，但不会拖累列表。

另外：rebase 删了 `t2脑图样例.swift`，旧的 `.xcodeproj` 一直引用它，直接 build 会报 “Build input file cannot be found”；跑一次 `xcodegen generate` 就好（`build.sh`/`device.sh` 里都会跑）。
